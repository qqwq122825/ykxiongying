# 星辰项目：Ubuntu 24.04 + 宝塔图形化重新部署说明

> 适用于全新服务器、换服务器和清空后重装。  
> 本说明对应当前仓库和 `yk.91dms.com`，不是旧版 V7 教程的修改稿。  
> 原则：除首次 `git clone` 和安装完成后生成 frps 目录的一次性脚本外，站点、PHP、数据库、SSL、伪静态、Node 项目和防火墙都通过宝塔图形界面配置。

---

## 1. 固定信息

| 项目 | 值 |
|---|---|
| 操作系统 | Ubuntu 24.04 LTS |
| 项目目录 | `/www/wwwroot/yk` |
| 站点运行目录 | `/www/wwwroot/yk/public` |
| 域名 | `yk.91dms.com` |
| PHP | 8.2 |
| MySQL | 8.0 |
| Node.js | 20 LTS |
| WebSocket 目录 | `/www/wwwroot/yk/node-ws` |
| WebSocket 内网端口 | `127.0.0.1:8889` |
| FRPS 目录 | `/www/wwwroot/yk/frps` |
| FRPS 服务端口 | `7000/TCP` |
| FRPS Dashboard | `127.0.0.1:7500` |
| 设备隧道端口 | `19902-29999/TCP` |

### 与旧教程不同的地方

- 前端已编译到 `public/assets/`，站点不需要单独运行 `8888` 端口。
- WebSocket 由域名的 `/ws/` 反向代理进入 `127.0.0.1:8889`，不需要对公网开放 `8889`。
- 不手工安装全局 PM2；只在宝塔 **Node 项目** 中管理 WebSocket 和 FRPS。
- 不导入旧数据库备份；新服务器使用 `/install/` 生成干净数据库。
- `/ws/`、`/apk_output/`、安装入口和 ThinkPHP 重写全部放在当前站点的 **伪静态** 页面；不再创建 `00-project.conf`。

## 2. 准备 Ubuntu 和宝塔

### 2.1 安装宝塔后的基础套件

在宝塔 **软件商店** 安装：

- Nginx；
- MySQL 8.0；
- PHP 8.2；
- phpMyAdmin；
- Node 版本管理器，并安装 Node.js 20 LTS；
- Java 环境管理器，并安装完整 JDK 11 或更高版本。

当前项目不依赖 Redis 才能启动，可以后续再配置。

### 2.2 PHP 扩展

进入 **软件商店 → PHP 8.2 → 安装扩展**，确认：

```text
pdo_mysql
mbstring
ctype
curl
gd
openssl
fileinfo
zip
opcache
```

进入 **PHP 8.2 → 配置修改**：

```ini
memory_limit = 1024M
max_execution_time = 800
upload_max_filesize = 200M
post_max_size = 200M
```

进入 **PHP 8.2 → 禁用函数**，从禁用列表移除项目需要的：

```text
exec
shell_exec
system
passthru
putenv
proc_open
proc_get_status
```

### 2.3 APK 构建环境

安装页会在提交前检查并显示实际路径：

- Java/JDK 11+；
- `keytool`（必须是完整 JDK，不能只装 JRE）；
- Python 3；
- `unzip`；
- 仓库内置 `extend/apksigner.jar`；
- 仓库内置 APK 签名脚本。

任一必需项缺失时，`/install/` 会拦截安装，先在宝塔软件商店补齐再刷新页面。

## 3. 拉取代码（唯一的 SSH 代码操作）

在服务器上建好空目录 `/www/wwwroot/yk`，再把私有仓库直接克隆到当前目录，不能再多一层仓库文件夹：

```bash
cd /www/wwwroot/yk
git clone <PRIVATE_REPOSITORY_URL> .
```

私有仓库使用 GitHub Deploy Key、SSH Key 或只读 Token，不把 GitHub 密码写入教程、项目文件或 `.env`。

克隆后，宝塔文件管理器中应直接看到：

```text
/www/wwwroot/yk/app
/www/wwwroot/yk/public
/www/wwwroot/yk/node-ws
/www/wwwroot/yk/install
/www/wwwroot/yk/deploy
```

## 4. 用宝塔创建 PHP 站点

进入 **网站 → PHP 项目/传统项目 → 添加站点**：

| 字段 | 填写 |
|---|---|
| 域名 | `yk.91dms.com` |
| 根目录 | `/www/wwwroot/yk/public` |
| PHP 版本 | `8.2` |
| 数据库 | 先不导入历史 SQL，使用第 6 节的空数据库 |

进入 **网站目录**，再确认运行目录是 `/www/wwwroot/yk/public`。不要填项目根目录，也不要填 `frontend-react`。

进入 **默认文档**，保证 `index.php` 在 `index.html` 之前。

---

## 5. 文件权限

在宝塔 **文件** 页面中设置：

- 普通目录：`755`；
- 普通文件：`644`；
- `runtime/`、`public/storage/`：所有者 `www`，目录权限 `775`，应用到子目录；
- `runtime/apk_build_queue/`、`runtime/apk_assets/`、`runtime/apk_output/`：重点确认为 `775 / www`；
- `public/assets/`及 `css/`、`js/`：至少 `755`。

如果首页空白且 `/assets/*.js` 返回 `403`，先检查静态目录是否被设成了 `700`。

---

## 6. 创建干净数据库并运行安装向导

### 6.1 创建空数据库

进入宝塔 **数据库 → MySQL → 添加数据库**：

- 数据库名、用户名和密码使用当次部署的新值；
- 访问权限选择本地服务器；
- 字符集使用 `utf8mb4`；
- 不导入历史 SQL 备份。

### 6.2 打开安装向导

访问：

```text
https://yk.91dms.com/install/
```

填写数据库、管理员、网站地址、WebSocket 和 FRPS 信息。WebSocket 地址填：

```text
wss://yk.91dms.com
```

保持勾选：

```text
清空旧 fisher_ 表后安装干净数据库（保留内置注入模板库）
```

安装成功后的初始状态：

- 设备 `0`；
- APK 构建记录 `0`；
- 历史子账号 `0`；
- 只有安装页填写的管理员；
- 保留内置注入模板、权限菜单和角色权限。

安装成功会生成：

```text
/www/wwwroot/yk/.env
/www/wwwroot/yk/runtime/install.lock
```

普通更新不删除 `install.lock`。

## 7. 在宝塔伪静态中粘贴完整站点规则

进入 **网站 → yk.91dms.com → 设置 → 伪静态**：

1. 选择“当前”，不选宝塔内置 ThinkPHP 模板；
2. 清空编辑器的旧内容；
3. 完整粘贴 `deploy/宝塔Nginx伪静态_ThinkPHP6.conf`；
4. 点击“保存”；
5. 保存后再切换页签并重新打开“伪静态”，确认内容仍然存在。

这一份规则已包含：

- `/ws/` WebSocket 反代；
- `/apk_output/` APK 下载目录；
- `/install`、`/install/` 安装入口；
- `/s/bn/native` 旧版 APK 联通探测；
- ThinkPHP 统一入口。

不要在“配置文件”、“反向代理”或站点扩展目录再写一份。如出现：

```text
duplicate location "/ws/"
duplicate location "/apk_output/"
duplicate location "/"
```

说明同一个 `location` 存在两份；保留伪静态这一份，清除其他位置的旧副本。不要建立全局 Nginx 配置。

## 8. 生成并启动 FRPS

安装完成页会显示一条一次性命令：

```bash
sudo bash /www/wwwroot/yk/deploy/install-frps.sh
```

这一步只从仓库内置、已校验的包生成 `/www/wwwroot/yk/frps/`，不用来守护服务。服务启停仍由宝塔图形界面管理。

然后进入 **网站 → Node 项目 → 添加项目**：

| 字段 | 填写 |
|---|---|
| 项目目录 | `/www/wwwroot/yk/frps` |
| 启动选项 | `start` |
| 运行用户 | `root` |
| 项目名 | `frps` |

只保留这一个 FRPS 项目，防止 `7000` 端口冲突。服务器上不运行设备侧 `frpc`。

---

## 9. 创建 WebSocket Node 项目

进入 **网站 → Node 项目 → 添加项目**：

| 字段 | 填写 |
|---|---|
| 项目目录 | `/www/wwwroot/yk/node-ws` |
| Node 版本 | 20 LTS |
| 启动选项 | `start` |
| 端口 | `8889` |
| 运行用户 | `www` |
| 包管理器 | npm |
| 安装命令 | `npm ci --omit=dev` |

只保留一个 WebSocket 项目。不再另建 `fisher-ws-server`、不再建同名 PM2 任务、不手工运行 `node src/index.js`。

宝塔项目显示“运行中”后，站点顶部应能看到 WebSocket 状态。

## 10. SSL

进入 **网站 → yk.91dms.com → 设置 → SSL**：

1. 申请 Let's Encrypt 证书；
2. 确认证书包含 `yk.91dms.com`；
3. 开启强制 HTTPS；
4. 保持宝塔自动续期。

证书申请和续期只在宝塔图形界面操作。

---

## 11. 防火墙和安全组

在宝塔 **安全中心** 以及 VPS 提供商安全组中配置。

### 需要对公网开放

| 端口 | 用途 |
|---|---|
| `80/TCP` | HTTP/证书校验 |
| `443/TCP` | HTTPS |
| `7000/TCP` | 设备 FRP 连接 |
| `19902-29999/TCP` | 设备隧道 |
| SSH 端口 | 仅管理使用，建议限制来源 IP |

### 不对公网开放

| 端口 | 原因 |
|---|---|
| `8889` | 由 Nginx `/ws/` 反代 |
| `7500` | FRPS Dashboard 只监听 `127.0.0.1` |
| `3306` | MySQL 只本机访问 |
| `6379` | Redis 如使用也只本机访问 |

宝塔面板端口只允许管理 IP 访问。

## 12. 首次上线验收

按以下顺序检查：

1. `https://yk.91dms.com/` 能显示管理页；
2. `https://yk.91dms.com/install/` 显示“系统已安装”和 `runtime/install.lock`；
3. `/api/auth/check-initialization` 返回 JSON，不是前端 HTML；
4. 宝塔 WebSocket Node 项目显示“运行中”；
5. 网站设备页显示 `WS在线`，设备卡片显示 `WS ✓`；
6. FRPS 项目显示“运行中”，且没有 `7000` 端口冲突；
7. 新建一次测试 APK 构建，任务从排队变成已完成；
8. 点击下载，`/apk_output/<文件名>.apk` 返回 APK 文件，不返回前端 HTML；
9. 宝塔 Nginx 配置保存不出现 `duplicate location`。

## 13. 普通更新（不重新安装）

更新前先用宝塔备份数据库和项目根目录 `.env`。

仅更新代码时：

```bash
cd /www/wwwroot/yk
git pull --ff-only origin main
```

然后在宝塔图形界面：

1. Composer 依赖有变化时，在 PHP 项目的 Composer 功能重新安装；
2. `node-ws/package-lock.json` 有变化时，在 Node 项目中重新安装依赖；
3. 重启 WebSocket Node 项目；
4. 只有 FRPS 程序或配置有变化时才重启 FRPS；
5. 重载 Nginx；
6. 重复执行第 12 节的验收。

只有 `frontend-react/src/` 变化且仓库没有带新的 `public/assets/` 时，才需要重新执行前端依赖安装和构建。普通 `git pull` 后不必每次执行 `npm install` 和 `npm run build`。

不要删除 `runtime/install.lock`，不要重新打开安装流程，不要导入历史 SQL。

## 14. 常见故障

### 伪静态保存失败：`duplicate location`

同一个 `location` 在伪静态和其他配置中同时存在。保留伪静态中的完整版，清理站点配置、反向代理或扩展目录中的旧副本。

### 构建任务一直排队

检查 WebSocket Node 项目是否运行。它同时负责 WebSocket 和 APK 构建队列。

### APK 签名失败

重新打开 `/install/` 查看环境检查结果，重点确认 JDK 11+、`keytool`、Python 3、`unzip`和仓库内置签名工具。

### `runtime/apk_build_queue` 权限报错

在宝塔文件管理器中把该目录设为 `775 / www`，并应用到子目录。

### `7000` 端口冲突

宝塔 Node 项目中只保留一个 FRPS 项目，停止并删除旧的命令行进程或重复项目后再启动。

### 网页可打开但 WebSocket 不通

确认：

- Node 项目监听 `127.0.0.1:8889`；
- 伪静态中的 `proxy_pass` 是 `http://127.0.0.1:8889`，末尾不加 `/`；
- 伪静态只有一份 `/ws/`；
- 域名已启用 HTTPS，安装页 WebSocket 地址是 `wss://yk.91dms.com`。

## 15. 最终禁止项

- 不把项目放成 `/www/wwwroot/yk/仓库名/...`；
- 不把站点根目录指向 `frontend-react`；
- 不对公网开放 MySQL、Redis、`7500`和 `8889`；
- 不创建额外 PM2 任务；
- 不用全局 Nginx 配置代替当前站点配置；
- 不在多个位置重复定义 `/ws/`、`/apk_output/` 或 `location /`；
- 不把历史设备、账号、构建记录和表单数据带入新安装；
- 不在日常更新时删除 `runtime/install.lock`。
