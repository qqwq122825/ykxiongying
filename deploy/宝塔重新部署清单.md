# 宝塔重新部署清单（yk.91dms.com）

这份清单用于全新服务器、换服务器和清空后重装。除首次 `git clone` 外，网站、PHP、数据库、SSL、伪静态和 Node 项目均在宝塔图形界面配置。

## 一、固定目录和服务

| 项目 | 配置 |
|---|---|
| 项目目录 | `/www/wwwroot/yk` |
| 网站运行目录 | `/www/wwwroot/yk/public` |
| 域名 | `yk.91dms.com` |
| PHP | PHP 8.2（项目要求 PHP >= 8.0；当前服务器使用 8.2） |
| Node WebSocket | `/www/wwwroot/yk/node-ws`，脚本选择 `start`，监听 `127.0.0.1:8889` |
| FRPS | `/www/wwwroot/yk/frps`，脚本选择 `start`，服务端口 `7000` |
| FRPS Dashboard | 仅监听 `127.0.0.1:7500`，不对公网开放 |
| 设备隧道端口 | `19902-29999/TCP` |

## 二、部署前环境准备

### 1. 操作系统与宝塔软件

- 推荐全新 `Ubuntu 24.04 LTS`。
- 在宝塔 **软件商店** 安装 Nginx、MySQL 8.0、PHP 8.2、phpMyAdmin 和 Node 版本管理器。
- 在 Node 版本管理器中安装 Node.js 20 LTS。
- Redis 可以安装作为后续扩展，但当前主代码不依赖 Redis 才能启动。

### 2. PHP 扩展和参数

在 **软件商店 → PHP 8.2 → 安装扩展** 启用：

```text
pdo_mysql
mbstring
ctype
curl
gd
openssl
fileinfo
zip
opcache（生产环境建议）
```

在 **PHP 8.2 → 配置修改** 检查：

```ini
memory_limit = 1024M
max_execution_time = 800
upload_max_filesize = 200M
post_max_size = 200M
```

在 **PHP 8.2 → 禁用函数** 中移除项目需要的 `exec`、`shell_exec`；如 Composer 或构建流程报函数被禁用，再检查 `putenv`、`proc_open`、`proc_get_status`、`passthru`、`system`。

### 3. APK 构建环境

构建服务会调用 Python 3、Java、`unzip` 以及仓库内置的 `apksigner`。

在宝塔 **软件商店** 安装“Java环境管理器”，再在插件里安装 **JDK 11**。构建脚本会依次查找：

1. `PATH` 中的 `java`；
2. `JAVA_HOME/bin/java`；
3. `/usr/bin/java`；
4. 宝塔目录 `/www/server/java/*/bin/java`。

没有 Java 时，APK 可以进入队列并完成打包，但会在“签名与校验 APK”阶段失败。Python 3 和 `unzip` 也必须存在。

项目已内置 Linux `apksigner` 脚本和 JAR，无需另外下载整套 Android SDK。

### 4. Composer 与项目依赖

- 在宝塔 PHP 项目的 Composer 功能中，以 `/www/wwwroot/yk/composer.lock` 安装生产依赖。
- Node WebSocket 项目使用 `/www/wwwroot/yk/node-ws/package-lock.json`，依赖安装选择 `npm ci --omit=dev`。
- 只有需要重新生成前端资源时，才在 `/www/wwwroot/yk/frontend-react` 执行 `npm ci` 和 `npm run build`。
- 仓库已包含 `public/assets/` 时，首次上线不需要为了访问首页而再起一个 `8888` 前端服务。

## 三、全新部署顺序

### 1. 拉取代码

首次只把仓库内容放到 `/www/wwwroot/yk`，不要再多套一层仓库目录。完成后，宝塔文件管理器中应直接看到：

```text
/www/wwwroot/yk/app
/www/wwwroot/yk/public
/www/wwwroot/yk/node-ws
/www/wwwroot/yk/install
```

### 2. 宝塔创建 PHP 网站

在 **网站 → PHP项目/传统项目 → 添加站点**：

- 域名：`yk.91dms.com`
- 根目录：`/www/wwwroot/yk/public`
- PHP 版本：`8.2`
- 默认文档顺序：`index.php index.html`

根目录不能填 `/www/wwwroot/yk`，也不能填 `frontend-react`。

### 3. 文件权限

在宝塔文件管理器中设置：

- 项目目录及普通子目录：`755`
- 普通文件：`644`
- `runtime/`、`public/storage/`：所有者 `www`，目录权限 `775`，勾选“应用到子目录”
- 重点确认 `runtime/apk_build_queue/`、`runtime/apk_assets/`、`runtime/apk_output/` 都显示 `775/www`
- `public/assets/` 及其 `css/`、`js/` 子目录：至少 `755`

如果首页空白且 `/assets/*.js` 返回 `403`，先检查 `public/assets/css` 和 `public/assets/js` 是否误设成了 `700`。

### 4. 伪静态、APK 下载和 WebSocket

进入 **网站 → yk.91dms.com → 设置 → 伪静态**：

1. 不选择宝塔内置模板，保持“当前”。
2. 清空原内容。
3. 完整粘贴 `deploy/宝塔Nginx伪静态_ThinkPHP6.conf`。
4. 保存。

这一份伪静态规则已包含当前站点需要的全部自定义 `location`：

- `/ws/` → `127.0.0.1:8889` WebSocket 反代；
- `/apk_output/` → `/www/wwwroot/yk/runtime/apk_output/`；
- `/install`、`/install/` → `install.php`；
- `/s/bn/native` 旧版 APK 兼容；
- 其他不存在的文件 → ThinkPHP `index.php`。

不需要再单独添加 `/api/`、`/spi/` 或 `/m/`：当前代码只注册 `/api/` 和 `/spi/`，统一入口规则会处理它们；旧项目的 `/m/` 规则不属于当前版本。

`/ws/` 和 `/apk_output/` 只保留在此站点的 **伪静态** 页面中，不再创建 `00-project.conf`，也不再从“配置文件”或“反向代理”重复添加。保存时如出现 `duplicate location`，先删除其他位置的旧副本，保留伪静态这一份。

### 5. 数据库与安装向导

在宝塔 **数据库** 页面创建空数据库和账号，然后访问：

```text
https://yk.91dms.com/install/
```

填写数据库、管理员、域名、WebSocket 和 FRPS 信息。保持下面的选项勾选：

```text
清空旧 fisher_ 表后安装干净数据库（保留内置注入模板库）
```

安装后的预期状态：

- 设备：`0`
- APK 构建记录：`0`
- 历史子账号：`0`
- 管理员：只有安装页填写的账号
- 注入模板：保留内置模板库

不要手工导入仓库根目录的历史 SQL 备份。

### 6. Node WebSocket 项目

在宝塔 **Node 项目 → 添加项目**：

- 项目目录：`/www/wwwroot/yk/node-ws`
- Node：20 LTS
- 启动脚本：`start`
- 端口：`8889`
- 项目用户：`www`
- 包管理器：`npm`
- 安装命令：`npm ci --omit=dev`

只保留一个 WebSocket 项目实例，避免 `8889` 端口冲突。不需要额外创建同名 PM2 任务。

### 7. FRPS 项目

先按安装完成页给出的路径生成 `/www/wwwroot/yk/frps/`。随后在宝塔 **Node 项目 → 添加项目**：

- 项目目录：`/www/wwwroot/yk/frps`
- 启动脚本：`start`
- 项目用户：`root`（FRPS 需要绑定隧道端口）

服务器上只运行 `frps`；不要运行设备侧 `frpc`。

### 8. SSL

进入 **网站 → yk.91dms.com → SSL**：

1. 申请 Let's Encrypt 证书；
2. 开启强制 HTTPS；
3. 确认证书域名包含 `yk.91dms.com`。

证书只通过宝塔图形界面申请和续期。

### 9. 防火墙/安全组

公网开放：

- `22/TCP`（SSH，建议限制来源 IP）
- `80/TCP`
- `443/TCP`
- `7000/TCP`
- `19902-29999/TCP`

宝塔面板的自定义端口只对管理 IP 开放。网页通过 `/ws/` 反代时不需要公网开放 `8889`。`7500`、`3306`、`6379` 仅绑定本机，不对公网开放。

## 四、代码更新而不是重装

普通更新不删除 `runtime/install.lock`，也不重新运行安装向导：

1. 先备份根目录 `.env` 和数据库；
2. 更新代码；
3. 如果 `frontend-react/src/` 有变化，在宝塔对应项目的构建功能中执行前端构建；
4. 检查 `public/assets/` 新文件权限为 `755/644`；
5. 在宝塔中重启 Node WebSocket 项目；
6. 只有 FRPS 配置或程序变化时才重启 FRPS；
7. 在宝塔中重载 Nginx。

只有明确要清空数据库重新安装时，才删除 `runtime/install.lock` 并再次访问 `/install/`。

## 五、上线验收

依次确认：

1. `https://yk.91dms.com/` 返回页面，浏览器控制台无静态资源 `403`；
2. `https://yk.91dms.com/install/` 在已安装状态显示锁文件提示；
3. `/api/auth/check-initialization` 返回 JSON，而不是前端 HTML；
4. WebSocket `/ws/panel` 能升级连接；
5. 完成一次测试 APK 构建，`/apk_output/<文件名>.apk` 返回文件而不是前端 HTML；
6. 宝塔 Node 项目中 WebSocket 服务为“运行中”，端口 `8889` 只有一个进程占用；
7. FRPS 为“运行中”，端口 `7000` 正常监听；
8. 新建一次测试构建并查看宝塔项目日志；页面出现“构建任务创建失败”时，说明网页和 API 已经通到后端，应继续检查 PHP/Node 构建日志、目录权限和构建依赖，而不是继续修改伪静态。

常见构建故障：

- `file_put_contents(.../runtime/apk_build_queue/...): Permission denied`：在宝塔文件管理器把 `runtime/apk_build_queue` 设为 `775/www`，并应用到子目录。
- 任务能进入“排队中”但一直不开始：Node WebSocket 项目没有运行；它同时负责 `/ws/` 和 APK 构建队列，必须在宝塔 Node 项目中保持“运行中”。
